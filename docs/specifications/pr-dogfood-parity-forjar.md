## 4. Decisions that are the operator's (not resolved here; the lane's recommendation and its strongest counter, then the orchestrator's)

1. Whether the Quorum CI job becomes a REQUIRED check in ruleset 13878864 (forjar cannot do this; bashrs can — it is the stronger position, and it also means the pre-push hook is fast feedback rather than the only enforcement). Lane: YES; counter: an emergency hotfix can no longer bypass with `--no-verify`. Orchestrator: YES — the bypass that remains is the committed `waived.reason` string, which is visible in the PR, which is the point.
2. Whether the quorum floors apply retroactively to PRs merged in the 7.0.5 window before the gate exists (forjar set `harness_floor`/`dogfood_floor` at the release the gates landed in). Lane: floors at v7.0.5; counter: PRs merged between v7.0.4 and the gate's landing lack receipts and would keep gate E red unless backfilled. Orchestrator: floors at the first tag AFTER the gates land (v7.0.6 or v7.1.0), exactly as forjar did with `harness_floor: v1.26.0`; no backfill.
3. The CRUX roster for bashrs (§2) and how gate H counts it. First review: reject format-specific linters, shell linters only; counter: bashrs lints Makefiles and Dockerfiles (MAKE*/DOCKER* rules, with their own corpus sections), so those tools are its direct competitors there. Second review: the first draft named ONE system per non-shell format (checkmake; hadolint) — a KILL, accepted. Orchestrator: §2 now names ≥3 per format, and gate H should count ≥3 systems of the bullet's own format — a MAKE010 bullet compared only against shellcheck is compared against nothing.
4. Whether `make dogfood`'s current advisory self-lint (bashrs on its own scripts) becomes a gate with a ratchet (`legacy errors ≤ N`, forjar's CB-200 ratchet shape) — comply CB-400 already counts 1,253 errors on the repo's own scripts. Lane: YES; counter: a ratchet pinned at 1,253 means friction on every PR that touches a legacy script. Orchestrator: YES, but the ratchet counts per FILE (forjar's `legacy bashrs errors 1 <= 1` shape), so a PR only pays for the files it touches.
5. Whether bashrs adds a `kind: docs` rail (`docs/**`, `book/**`, `README.md`, `CHANGELOG.md`) beside `kind: triage`, or keeps forjar's position that an enforced author's docs PR carries a full receipt (forjar holds four `docs-*.json` receipts). Second review: add the rail, or the required check blocks docs work. Orchestrator: keep forjar's position for one release and measure the friction; the receipt for a docs PR is cheap (`falsification.not_applicable` with a reason), and a rail added before it is needed is a bypass added before it is needed.
6. Whether `quorum.yml` runs the gate script and `enforce.json` from the base branch rather than the PR's own copy. Third review: yes — otherwise an enforced author weakens the gate in the same PR it judges. Counter: a change to the gate cannot be tested by the PR that makes it (the old gate judges it), and the very first PR that adds the gate is judged by nothing; forjar runs the PR's copy and relies on the edit being visible in the diff. Orchestrator: adopt — bashrs's check is REQUIRED, which forjar's is not, so the stronger position deserves the stronger rule; the bootstrap PR's receipt is read by hand, once.

## 5. Risks measured on forjar (copy the fixes, not the lessons)

- PR merge commit vs pushed head in CI (`quorum.yml` checks out `head.sha`, `fetch-depth: 0`).
- `QUORUM_BASE` env override was a one-word bypass — the base is a constant.
- Pre-push must read git's ref protocol before anything consumes stdin; the REMOTE ref decides exemption (`git push origin main:feature` bypass); the local sha is kept so a push of branch B from a branch A checkout resolves B's receipt (#400).
- `fail()` inside `$(...)` swallows the verdict — window.sh returns via globals.
- A skill named `dogfood` is shadowed by a user-scope skill — name it `bashrs-dogfood` and pin it with a test.
- Gate E once was prose discharged by an agent — a requirement without an exit code is not a gate.
- Hunk-level citation anchoring failed honest work at 25% — file-level 33% is the tuned floor.
- A truncation heuristic fired on a complete sentence — dropped; exact-budget and unclosed-backtick rules kept.
- The spec and the script drift (sixteen vs 15 leak patterns; `divergence` asked for and never asserted; "an empty diff is exempt" against a gate that rejects one; "≥3 of the surveyed systems" against a gate that counts its own hard-coded list) — bashrs's edition pins each floor with a falsification test the day it is written.
- Gate C (surface) is forjar-specific (CLI/MCP/HTTP); the bashrs analogue is not the corpus (a data set, its own gate K) but the RULE REGISTRY — every rule code the binary can emit is documented and every documented code is live.
